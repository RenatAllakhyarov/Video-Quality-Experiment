# Технические источники и принятые решения

Документ фиксирует сведения, проверенные по официальной документации на 10.10.2026. Он не заменяет две отсутствующие научные работы Лосева, перечисленные в `04_НЕПОЛУЧЕННЫЕ_МАТЕРИАЛЫ.md`.

## FFmpeg

Официальная документация FFmpeg описывает фильтры `psnr`, `ssim` и `libvmaf`. Для `psnr` и `ssim` входы должны иметь одинаковые разрешение и pixel format; кадры сопоставляются по порядку. Для `libvmaf` первый вход является искажённым, второй — референсным. Документация также фиксирует `log_fmt`, `log_path`, `pool` и `n_subsample`.

Источник: <https://ffmpeg.org/ffmpeg-filters.html>, разделы `libvmaf`, `psnr`, `ssim`.

## libvmaf / VMAF

Официальная документация Netflix VMAF указывает, что модель, версия, pixel format, bit depth и pooling должны фиксироваться. В libvmaf 2.x предпочтителен JSON-формат моделей; в новых сборках доступны встроенные модели. Для Windows путь к модели может потребоваться явно указать при вызове через FFmpeg.

Источники:

- <https://github.com/Netflix/vmaf/blob/master/libvmaf/README.md>
- <https://github.com/Netflix/vmaf/blob/master/libvmaf/tools/README.md>
- <https://github.com/Netflix/vmaf/blob/master/resource/doc/ffmpeg.md>

В проекте VMAF считается опциональным: если сборка FFmpeg не содержит `libvmaf`, PSNR и SSIM всё равно сохраняются, а поле VMAF получает `null` и диагностируется в логе.

## Методика проекта

- Референс обеих схем — исходное видео.
- `baseline`: исходник → кодирование → метрики относительно исходника.
- Эксперимент: исходник → предобработка → кодирование → метрики относительно исходника.
- Gamma-предобработка в текущем каркасе использует явно помеченную проектную конвенцию `y = x^γ` на нормированной 8-битной яркости.
- Контрастное растяжение использует `y = clip((x − x_min)·255/(x_max − x_min), 0, 255)` на яркости; границы задаются конфигурацией.

Эти две формулы нельзя приписывать отсутствующей работе Лосева до получения полного текста или письменного согласования альтернативного первоисточника.
